# CLAUDE.md — Buyer Scout PoC

Инструкции для Claude Code по этому репозиторию. Читай целиком перед первой задачей.

## Что это

Изолированный исследовательский PoC для KleekTo. Проверяет одну гипотезу: есть ли
в выбранных Telegram-группах достаточный поток уникальных контактируемых сигналов
от потенциальных покупателей недвижимости в Грузии.

Итоговая метрика эксперимента — **Contactable Qualified Buyers / Day**.

Полный концепт: `docs/CONCEPT.md`. Рубрика классификации: `docs/RUBRIC.md`.

## Жёсткие границы

Это PoC, а не продукт. НЕ делать без отдельного указания:

- не трогать репозиторий и архитектуру KleekTo, не импортировать оттуда код;
- не строить Buyer Feed UI — достаточно таблицы или простого дашборда;
- не делать Facebook- и WhatsApp-интеграции;
- не строить matching engine с Property Feed;
- не обучать собственную ML-модель;
- не создавать multi-agent framework;
- не закупать инфраструктуру под большой поток;
- **никогда не отправлять сообщения потенциальным покупателям** — ни автоматически,
  ни по запросу. PoC только обнаруживает и структурирует.

## Данные и приватность

Raw Message Store содержит персональные данные третьих лиц.

- `data/`, `*.db`, `*.sqlite`, `exports/`, `.env` — никогда не коммитить, они в `.gitignore`;
- не добавлять поля сверх перечисленных в `db/schema.sql`;
- мониторить только группы, явно перечисленные в `config/sources.yaml`;
- не обходить ограничения доступа платформы: если группа требует обхода — она
  исключается из выборки, а не обходится;
- `scripts/purge.py` должен уметь удалить все данные по одному источнику и всё
  старше N дней. Retention по умолчанию — 30 дней.

## Пайплайн

```
Telegram → Collector → Raw Message Store → Stage 0 (локальные правила)
       → Stage 1 (Haiku, релевантность)
       → Stage 2 (Haiku, intent + S-level + score)
       → Stage 3 (Sonnet 5, structured extraction)
       → Deduplication → Buyer Signals DB → таблица
```

Каждая следующая стадия дороже и получает меньший поток. Stage 0 бесплатна.

## Обязательные требования к вызовам Claude API

Это главный рычаг стоимости — нарушение удорожает прогон в разы.

| Требование | Stage 1 | Stage 2 | Stage 3 |
| --- | --- | --- | --- |
| Модель | `claude-haiku-4-5` | `claude-haiku-4-5` | `claude-sonnet-5` |
| Батчинг сообщений в один запрос | 50 | 20 | 1 |
| Prompt caching системного промпта | обязательно | обязательно | обязательно |
| Batch API (−50%) | обязательно | обязательно | обязательно |
| Ответ | JSON-массив по индексам | JSON-массив по индексам | structured output |

Дополнительно:

- системные промпты живут в `prompts/*.md` и загружаются из файлов, не хардкодятся;
- рубрика S1–S5 берётся из `docs/RUBRIC.md` — единственный источник истины,
  дублировать её в коде нельзя;
- поля, которых нет в тексте сообщения, остаются `unknown`. Модель не додумывает.
  На это должна быть отдельная проверка в тестах;
- логировать `input_tokens`, `output_tokens`, `cache_read_input_tokens` и расчётную
  стоимость каждого прогона в таблицу `pipeline_runs`.

## Что измеряем

Все метрики пишутся в БД и выгружаются в `docs/METRICS.md`:

Raw Messages/Day · Buyer Signals/Day · Qualified Buyer Signals/Day (S4–S5) ·
Unique Buyers/Day · Contactable Buyers/Day · Precision · False Positive Rate ·
Signal Latency · Source Yield (qualified на 1 000 сообщений источника).

Precision и False Positive Rate считаются по ручной проверке S4/S5 — их нельзя
получить автоматически, потому что проверяется как раз качество работы модели.
Нужен минимальный интерфейс разметки: `Good signal` / `Not a buyer` /
`Already contacted` / `Duplicate` / `Spam` / `Wrong location` / `Wrong intent`.

## Стек

Python 3.11+, SQLite для PoC (схема пишется так, чтобы переезд на Postgres был
механическим), Docker-контейнер, конфиг через `.env`. Без тяжёлых фреймворков.

## Порядок работы

1. Прежде чем писать код стадии — показать системный промпт и дождаться подтверждения.
2. Перед полным прогоном — тест на 200 сообщениях с оценкой стоимости полного прогона.
3. Каждая стадия мержится отдельно, со своими метриками в `docs/METRICS.md`.
4. Не переходить к следующей стадии, пока предыдущая не даёт стабильных цифр.
